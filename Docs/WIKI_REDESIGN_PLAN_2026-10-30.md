# W&W Wiki 改进规划

日期：2026-10-30。状态：规划，未宣称完成迁移。

## 判断与证据

## 产品边界

Wiki 是可独立使用的研究资料库；工坊、游戏题库、游戏资源构建是它的消费者和成果回存者。无三维模型、无文化归属、无工坊时仍能完成收录、检索、引用、修订、导出。摩梭人案例仅为一组数据，不能决定全站导航、字段和默认行为。

Wiki 原则落实为：稳定条目地址、可链接与反向链接、可追溯来源、渐进编辑、历史与讨论、允许未知和不同解释、资料可迁出。公共发布以后仍区分阅读、贡献、审定和发布权限，图片授权未知不自动公开。

## 信息模型

- 条目：对象、工艺、材料、服饰组合、地点或文化主题；稳定 ID 与可改标题/别名分开。
- 媒体：原图/视频/文件、哈希、来源、署名、权利状态；裁剪和缩略图为派生物，原件保留。
- 来源：书目/网页/用户提供资料，定位到页码、时间码或图像区域。
- 陈述：属性、值、来源定位、提出者、状态；文化归属/年代允许多条并存，不强迫单值确定结论。
- 关系：部件属于、参考、衍生自、使用材料、版本替代等有方向关系；集合与部件关系不能只靠单 parent_id 表达。
- 数字成果：模型、材质、节点配方、工程文件、预览配置，各自版本与生成来源。游戏适配不反向变成历史证据。
- 修订：编辑者、时间、摘要、差异与撤销；审定引用具体修订，源改动后提示重审。

先实现条目/媒体/来源/关系/成果/修订；陈述级审核在渐进迁移中接入，避免一次性建庞大知识图谱。

## 交互与视觉

主导航仅资料库、收件箱、集合；工坊作为工具入口，题库作为派生成果入口。首页为通用搜索与最近资料，不默认打开案例。

收录：粘贴图片/链接或拖入文件 → 即时生成可恢复草稿 → 类别可选 → 保存至收件箱。标题可暂用文件名。批量去重提示、批量分类；年代和文化无需先填。

查阅：图像优先，常用动作固定为编辑、关联、引用/导出；来源贴近对应陈述。查看、编辑、修订历史分明。返回列表保留搜索、筛选、滚动；对象关联使用名称搜索，不要求记 ID。

工作流：选条目/成果 → 在工坊打开 → 实验草稿 → 保存新成果版本 → 自动建立衍生关系。不会覆盖来源或原资产。没有预览能力则显示支持的文件操作，不静默回落到摩梭人模型。

方正细边、暖纸底、克制靛色、正文优先可读性。正文14–16px，元信息12–13px；不能用全站缩字解决空间问题。宽屏主内容加可收起属性栏；窄屏单列、抽屉编辑；预览独立全屏。键盘焦点、撤销、保存状态、错误恢复、触控目标保持明确。

## 动画与物理复用

先定位用户当前使用的百褶裙模拟器实际入口与运行文件；asset-workbench/src/skirt 的名字不能作为认定它就是完整参考实现的依据。建立功能清单与同输入对照记录，再提取共享 preview-runtime。不要继续复制动作公式和硬编码碰撞尺寸。

共享运行时包含：时间/暂停/单步/重播、姿态采样、布料求解、珠链求解、人体与家具碰撞、参数约束和状态快照。Wiki 和百褶裙编辑器使用同版本运行时。若宿主差异暂不能共享，先以独立编辑器加载资源清单接入，并明确能力边界，不能用简化替代宣称等价。

PreviewManifest 声明 assetRevision、rigProfile、motionSet、clothProfile、adornmentProfile、environment、单位与坐标系、capabilities。骨骼名由适配器映射；穿戴路径/承托和自由段由资产数据定义；家具网格与碰撞由同一场景定义导出。

参数区只显示当前资产实际支持的功能。动作速度与物理时间倍率分别定义。拖动进度应从确定初态重演或恢复检查点，而非任意重置后冒充同一物理状态。暂停冻结模拟，转观察相机不施加惯性；转身动作才产生惯性。保存参数预设、前后对照、碰撞可视化。

功能对齐验收：同模型、动作、材质、碰撞场景与步长，对照站立/不同配速行走/匀速与变速转圈/坐下/躺卧；检查腿裙家具接触、裙摆展开、珠串前搭与自由段、暂停单步和时间轴复现。单元测试不能替代真实运行与多角度视觉验收。

## 独立输入输出

本地单服务与模块化实现即可，无需微服务。结构化数据建议 SQLite + FTS，媒体独立按哈希存储；事务维护关系和修订。保留版本化 JSON/JSONL 与含媒体的完整可迁移包，不把 SQLite 文件当唯一出口。

服务端提供通用 CRUD/搜索/关系/修订/导入预检/导出接口。工坊通过 manifest 接收资源，通过成果 API 回存；游戏从指定修订的构建清单消费，不扫描 Wiki 页面。导入支持预检、冲突报告、幂等键和回滚；导出包含 ID、来源、关系、版本、权利状态及校验清单。空库导入后关系与媒体可完整恢复。

## 实施顺序与退出条件

1. 基线与纠错：备份当前库；列出模拟器实际能力；纠正未定义变量及坐标误判，保留案例数据。退出条件：真实页面加载、姿态/碰撞差异清单可复现。
2. 资料库解耦：引入成果与关系数据，移出页面中的案例常量，空库流程可用。退出条件：加入布艺/玩具等三个不同类别无需改页面代码；移除案例后站点仍正常。
3. 核心交互：收件箱、快速收录、通用详情、关联搜索、修订与导出。退出条件：首次使用者能无说明完成收录—查找—关联—导出；320/768/1440宽度无页面横向溢出，键盘可完成主流程。
4. 共享预览：按能力清单接入同一运行时与数据协议，修复动作中的接触。退出条件：两端同输入逐项对照，通过真实浏览器和多角度检查；未实现能力明确标注。
5. 迁移与独立性：旧 ID/链接重定向兼容，双读对照后切换，保留备份回滚。退出条件：完整导出至空库再导入无资料/关系/媒体丢失，连续导入不重复，无需启动游戏或工坊即可使用资料库。
6. 公共发布后续：权限、编辑历史/讨论、审核队列、公开授权筛选与备份恢复演练。域名上线单独执行。

最先交付的是通用资料库骨架和能力差距清单，而非再增加一个案例专属面板。规划验收不等于上述实现已完成。

## 用户补充：受众、说明书与工具入口（2026-10-30，优先于上文对应旧方案）

Wiki 同时服务普通玩家、共创者与开发者，承担资料库、游戏说明书、答题练习和共创入口职责。共享同一套条目与来源，不要求访客先选身份，也不为三类人复制三套内容。

主导航调整为「游戏指南」「资料库」「答题练习」，全局搜索贯通内容。「参与共创」集中提供贡献流程及成熟工具入口；收件箱、审核队列、开发接口进入对应工作区，集合放在资料库内部。此项替代上文“主导航仅资料库、收件箱、集合”。

游戏指南按玩家任务组织入门、操作、玩法系统、物品用途及常见问题，记录适用游戏版本。资料条目用独立的游戏用途区连接指南，文化事实和游戏规则不混写。只描述已经确认的玩法；规则改动触发关联说明复核。

答题练习支持按主题练习及按游戏规则模拟。练习提交后显示解析与来源；模拟按游戏规则结算并提供错题回看。题目、判分规则及版本与游戏共享，未确认的计时计分不自行发明。普通玩家只接触已审定且来源有效的题；草稿预览属于编辑工作区。题目版本与作答记录分开保存。

资产编辑器系列 toolkit 成熟后，Wiki 提供相关成果页的“在编辑器中打开”及共创入口的工具目录。传递成果 ID、修订与资源清单，保存后返回原条目并登记新的衍生成果。未成熟工具不显示无效入口，也不阻塞 Wiki、指南和练习建设。这一约定补充上文共享预览方案：Wiki 可提供浏览预览，完整创作流程由独立 toolkit 承担。

布局负责传达用途：图片占主区、属性邻近、引用紧随对应正文、常用操作固定在标题附近；编辑时才展开编辑控件。删除重复页面标题、类别和常识的标签，以及解释界面如何工作的长段落。保留影响判断的待核实、版本不兼容、保存与错误反馈；技术 ID、schema、导出细节进入开发详情。精简文案不能隐藏证据不确定性或损失控件的可访问名称。

验收补充：玩家无需理解开发概念便能找到玩法说明、完成练习和查看来源；共创者能完成收录、关联和成果回存；开发者能取得指定修订。未安装编辑器或没有三维模型时，Wiki 的阅读、编辑、检索、练习与导出仍能独立使用。主流程应靠布局和控件即可发现，不依赖次要标签和说明段落。

## 访谈定案与首批实施（2026-10-30）

用户已授权开始实现。Q1–Q12、Q14采用建议；Q13修正为一个统一题库，仅给被游戏采用的题目增加版本标记，不分两个池。关系带类型且反向可见；复用概念成为节点、数值为属性。套装总览整体左大图、部件右纵列，窄屏上下组织。部件可被多套装引用。参数实验形成新变体，不覆盖原版；生成器/参数/依赖版本绑定。toolkit成熟后跳转，Wiki仍保留参数调节面板。

首批已实现：玩家导航、首页、基于当前代码的基本操作说明、统一题库练习/解析/来源、game_versions采用字段与编辑；套装组合总览、类别筛选下部件独立显示、原始证据缩略图优先；页面模型映射移至assets/catalog.json，工坊来源随选中资产切换；搜索条件写入URL及过期响应保护。修复家具绑定的未定义T变量。

验证：66项Node测试通过，包含分组、不丢失部件、原图选择、题目采用标记持久化及无效输入回滚；关键静态文件及API HTTP 200。浏览器视觉未验收，测试结果不代表屏幕适配和物理展示已经合格。

待完成：多对多类型关系与编辑UI、跨内容全局搜索、完整游戏说明、参数schema与生成器版本协议、个人变体存储、编辑器一致性/真实物理复用、权限与修订工作流、独立迁入迁出全链路。当前仍用parent_id作兼容分组。基础练习已接通，但现有本地题目尚待审定，不能为了展示自动批准。游戏采用字段不改变旧game-export语义（仍导出全部有效已审定题目及其采用元数据）；后续游戏构建应显式按版本选题。
