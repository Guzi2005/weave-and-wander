# W&W Wiki：图像档案、考证与数字工坊方案

日期：2026-10-28  
阶段：架构与视觉概念；未实现网站、未部署，未修改游戏运行时代码。  
本目录原型由内置 imagegen 生成。图中的藏品、记录、数量与工坊结果是界面占位，不是考证资料，也不表示这些功能已经实现。

## 1. 定位与优先级

W&W Wiki 是以图像为入口、以来源和证据为骨架的研究档案，同时为游戏知识内容与数字化制作提供可追溯的数据。

开发期的核心路径：采集线索 → 整理对象 → 逐项考证 → 关联数字作品 → 审核发布。
公开期的核心路径：检索与阅读 → 查看证据 → 收藏专题 → 进入工坊 → 提交创作或纠错。

优先让人能在几十秒内收下一张图，而不是把录入变成必须完成的学术表格。时期、文化与社群、地点均允许未知。未知、有争议、尚未整理、来源未补分别表达，不互相替代。

## 2. 页面与信息架构

### 收件箱与快速收录

拖入图片、粘贴图片、粘贴来源网页或上传批次。最小输入是图片或链接，大体类别可以选服装、饰品、布艺、玩具、工具、其他、待分类；笔记自由填写。标题可用描述性暂名。

系统记录稳定 ID、录入者、录入时间、源链接、文件哈希；有来源时保留原始标题与访问时间。对缺失出处使用待补状态，不为了通过校验伪造网址。允许先只有链接而没有本地图片。

批量任务包括缩略图生成、文件去重、候选相似图、OCR 和可选标签建议。OCR 与机器建议保存为机器生成记录，人工采纳后才能成为正式标注。完全相同文件可以复用媒体，来源采集记录不能被去重合并掉。

### 图像资料库

图片占主要面积，可切换图墙和列表。大体类别、名称、来源、年代、文化与社群、地点、审核状态独立筛选。图片卡先呈现名称、来源、资料状态，不要求卡片容纳所有学术字段。

保存的专题如“褶与结构”“染织与纹样”是多对多研究集合，不改变物品原有分类。地图和时间轴是后续探索视图，不作为早期录入门槛。

### 资料详情与考证

大图、多视角缩略图、原图区域标注、对照查看与证据栏并置。看见什么、来源如何描述、研究者做了什么推断分层呈现。

同一实物的正面、背面、细节可归到一个对象；一张合照可框选关联多个对象。概念条目与具体对象分别建立。例如“褶裥”是概念，一件有馆藏编号的裙是具体对象。

每项关键结论可展开证据、异议与修订历史。公开摘要是经过选择的可读叙述，背后仍能回到逐项依据。

### 数字工坊

左栏显示参考图与来源，中间显示二维结构和三维预览，右栏显示参数、材料和转译说明。持续显示作品属于考证复原、依据参考的改编或自由创作中的哪一类；“考证复原”同样需要审查，不由作者勾选后自动认证。

先连接已有百工纹样与百褶裙编辑器，再考虑统一复杂的二维纸样编辑。界面中展示的参数化结构不承诺真实可缝制纸样或布料物理。

保存工程文件、作品版本、纹理、模型与引用清单。GLB 是可交换模型之一，工程文件承担可编辑参数；仅导出模型会丢失研究与制作上下文。

## 3. 核心数据模型

采用关系数据库，稳定 ID 贯穿各模块。原始数据与修订可追溯，不把所有信息塞入单个不可约束的自由 JSON。

- Capture：一次采集。记录收集者、时间、原始链接、随手记和整理状态，可关联零到多个后续对象。
- Source：出处。网页、论文、书籍、馆藏目录、访谈、田野记录等；记录作者、题名、出版或记录时间、页码体系、永久标识与访问时间。转发页面和原始出处分别保存并建立关系。
- Media：媒体及其具体版本。图片、扫描件、音视频；保存校验值、尺寸、文件位置、访问规则与出处。裁切、抠图、增强和生成图分别作为派生媒体，不覆盖原件。
- Record：具体物品、服装组合或文化概念。用 record_type 区分，可关联多个媒体；名称保存原文、转写、译名与别名。
- Claim：关于某个对象某项属性的论断。内容、提出者、证据、证据位置、审核者、审核时间、状态、替代关系。相互矛盾的论断可以并存。
- Annotation：对图像区域、文献段落或视频时间片的观察与说明。锚定媒体的具体版本，记录坐标基准与图像尺寸，变换后明确映射，不默默漂移。
- DigitalAsset：数字作品及版本。模型、纹样、参数化设计、纹理；记录所依据的对象、媒体区域、论断版本和作者转译说明。
- Question：题目及版本。题干、选项、答案、解释、语言、难度、关联论断版本、证据、审题状态。
- Collection：研究专题与策展集合。
- Release：审核后的发布快照，列出精确内容版本、文件哈希、许可信息与撤回状态。

Media 与 Record 多对多；Claim 与 Evidence 多对多；DigitalAsset 可引用多条资料与多个图像区域。Source 不是单纯的图片 URL。文件所在路径不是资料身份。

年代采用起止区间、原始表述、精度和依据，并区分制作时间、使用时间、拍摄时间和采集时间。地点区分制作地、使用地、采集地与现藏地；不能从收藏机构地址推导文化归属。历史地名与现代行政区并存。

文化与社群允许多值、关系类型和有争议的归属，保留来源中的原称、当代规范名称与社群自称；民族标签不能仅由纹样相似性自动确定。

## 4. 技术架构与部署边界

第一阶段建议模块化单体：一个 Web 应用、一个业务 API、PostgreSQL、对象存储、一个异步任务进程。按采集、档案、考证、作品、题库和发布组织模块。前后端可采用 TypeScript；选定具体框架应以维护能力和已有工具整合成本为准。

数据库存结构化关系、修订与审核；对象存储保存原始媒体、派生媒体和大体积模型。媒体对象使用稳定键与哈希，数据库保存引用。每日数据库备份与媒体清单备份配套，并实际演练恢复，不能把备份误当作已验证的恢复能力。

搜索先覆盖名称、别名、来源、笔记、受控标签和筛选。中文分词与异体、异名检索需用真实样本验证，不假设默认全文检索足够。相似图检索与专用搜索服务在有实际需求后添加。

异步任务承担缩略图、OCR、媒体转换、导出和发布，具有幂等键、失败重试与可见任务状态。链接元数据抓取由后台受限执行，不读取本地或内网资源。工坊导出使用隔离任务，限制输入格式、大小和计算时间。

数据流：
内部研究 Web → API → 数据库 / 私有媒体
内部研究 Web → 审核与发布 → 公开数据投影 / 获准公开的媒体 / 公开搜索索引
审核与发布 → 带版本号知识包、资产关联清单 → Godot
工坊 → 作品草稿与版本 → 审核后作品目录

内部资料与公开资料共享事实来源，但公众接口只读明确发布的数据投影。授权必须在 API、对象读取和搜索索引层生效；隐藏前端按钮不足以隔离资料。公开清单排除个人笔记、受限访谈、敏感精确位置、本机绝对路径和私有媒体地址。

多人协作先用修订号检测编辑冲突与审稿队列；不必在 MVP 同时做复杂实时协同编辑。公众纠错生成建议修订，审核后合并；保留稳定链接与变更说明。

## 5. 与当前游戏的接合

只读核查的现有接点：

- scripts/garment_definition.gd 有 design_id、collection_id、source_design_path、material_data。
- scripts/material_ledger.gd 的材料记录保留 pattern_id、pattern_revision、source_ids。
- scripts/pleated_skirt_design.gd 的 v1 合同限定 source.note 与 references[{title,path}]，并拒绝未知字段。
- tools/baigong-pattern-studio/ 已有网页编辑器与交换相关文件，可作为逐步整合的候选入口，尚未在本方案中验证端到端互通。

第一步增加独立资产关联 manifest：design_id → wiki_record_id、record_revision、source_ids、asset_revision、translation_note。不要直接把新增 Wiki 字段塞进现有百褶裙 v1 文件；升级协议时再做显式版本迁移与往返测试。

库存中的单件 item_id、服装设计 design_id、档案对象 record_id 分别表示不同层次，不互相替代。

Godot 使用经过审核的离线内容包，固定题目、论断、引用与资产版本。Wiki 实时编辑不会直接改变已发行游戏。建立来源修订到题目、资产、发行包的依赖关系，用于提示复查；下一个发布包处理更新或撤回。

导出包自动检查缺失引用、未审题目、未批准媒体、文件哈希和本机路径。授权不明的参考图片默认不随模型或游戏分发；引用清单可以保留获准公开的元数据与链接。

## 6. 研究状态、公开状态与文化协作

至少三组独立状态：整理阶段、论断审查状态、使用与发布权限。不能用“完成度 100%”混淆可信度与信息完整性。

出处是否可核验、图像可否展示、可否下载、可否修改、可否随商业游戏发布分别记录。照片、元数据、访谈、数字模型和玩家作品可具有不同的许可；归属字段不能代替许可判断。

设置贡献者、研究编辑、审校者、发布者等角色；团队小时可由同一个人承担多种职责，但操作记录保留。未来让相关社群代表参与名称、语境与访问规则的修订。

Local Contexts 可作为社群协议的设计参考。真正采用其 Labels 时应由相关社群决定和授权，不能由项目方替社群自行贴标签。

## 7. 题库设计

题目必须关联具体论断版本与证据位置，答后能查看解释和资料。优先考查观察、结构、工艺和有明确依据的知识。存在争议的文化归属，可设计为来源比较题，不能强制压成单一正确答案。

AI 可协助拟题、OCR、描述和检索，但机器输出不成为历史证据，也不自动通过审题。若来源被修订或撤回，依赖它的题目自动进入复查队列。

## 8. 视觉系统

概念方向为“开放的织物资料室”。

背景暖纸白 #F4F1E9，正文墨色 #242B2B，主操作靛蓝 #314A62，提示少量朱红 #9A5449；低饱和鼠尾草绿可表示经过审核的状态。状态总有文字与符号，不仅靠颜色。最终实现需验证对比度、键盘操作、焦点样式与不同缩放下可读性。

页面标题使用克制的宋体气质，正文与元数据使用清晰黑体；ID、尺寸和版本可采用等宽字体。用户于 2026-10-28 明确确认方正、严肃、学术的 UI 风格：方角面板与矩形按钮，圆角控制在 0–2px，使用极细分割线和适度留白，避免胶囊标签与大圆角卡片。手工感来自图像、纸色与少量织线识别元素，不给整站强加某一种民族纹样。

档案图保持原有色彩和比例，整件服装默认完整可见。正文阅读区不用纸纹覆盖，避免干扰细节。只有进入游戏资产与工坊预览时才出现 W&W 的纸感人偶。

原型一：图像资料库 + 快速收录抽屉。
原型二：图像细节 + 可追溯证据与争议 + 关联数字资产。
原型三：引用图像 + 二维结构 + 三维纸感人偶 + 参数与导出清单。

这些原型用于确认布局和气质。界面中的示意物件、数量、记录与模型不作为真实档案导入；文案、来源位置和交互在实现阶段进一步精确化。三张图独立生成，图标、侧栏分类和示意裙装存在细节差别，实施时应统一组件与词表。工坊中的人偶只说明预览布局，不替换游戏当前锁定的人物美术基准。

## 9. 分阶段交付与验收

第一阶段：采集箱、图像资料库、详情与证据、最小发布清单、备份导出。
验收：几十秒收录一条线索；未知字段不阻塞保存；按粗分类找回；从结论回到具体出处；能把一个现有 design_id 关联到可追溯资料版本；内部图像不出现在公共导出包中。

第二阶段：多图对照、区域标注、批量整理、题库编辑、关联清单与 Godot 离线包。
验收：一张图关联多个对象、一件物关联多张图；来源修订能定位受影响题目；资产和引用能随版本一起导出；旧游戏包保持内容不变。

第三阶段：公开检索、专题策展、纠错投稿、机构与社群合作、引用与下载接口。
验收：公众只能访问已发布内容；来源、署名和许可清楚；投稿不会未经审核改变条目；稳定链接与结构化导出长期可用。

第四阶段：在线工坊逐步统一，先纹样与百褶裙，后更复杂结构。
验收：从参考进入工坊、保存作品、重新打开、导出模型与工程、在游戏预览，全链路引用与版本不丢失。公开发布作品另走授权与审核流程。

- Local Contexts Labels：由社群定义和表达来源、使用协议与许可期待的机制。https://localcontexts.org/labels/about-the-labels/
- PostgreSQL 文本检索文档：检索与索引能力参考；本项目中文检索仍需单独验证。https://www.postgresql.org/docs/current/textsearch-intro.html
