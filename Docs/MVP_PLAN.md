# MVP 收敛计划

日期：2026-10-20。唯一游戏入口：`project.godot`。
本计划是下一轮实施范围，不表示功能已经完成。

## 可玩目标

做出能连续玩 15–20 分钟、完成一个营业日并保存继续的小店。
沿用已有三个房间、人物、街道及美术，不再新增建筑。
核心循环：采购材料/成品 → 制作与陈列 → 顾客挑选与试穿 →
员工收银打包 → 营业总结 → 根据反馈调整经营。

玩家至少能做三个有后果的决定：
- 进什么货、制作什么：成本、库存及顾客需求不同。
- 如何分配员工：收银、补货、制作与休息之间有取舍。
- 是否折扣：影响成交与利润，而不是只改变显示数字。

## P0：稳定现有闭环

- 收尾顾客排队、收银员在岗、商品单件身份、帽子置顶及装袋交接。
- 收尾休息姿势/蒙皮、通用表情及可中断过渡。测试通过与视觉验收分开。
- 增加端到端营业回归：固定随机种子，至少 30 位顾客；覆盖购买、
  拒购、无人收银、员工疲劳、取消任务、移动家具、暂停与加速。
- 验收：无崩溃、无重复扣款/售卖、库存数量与金额可对账、队列可恢复。

## P1：让玩家真正经营

- 增加营业开关、营业时段及关店清客；停止新客后让现有交易完成。
- 小型采购面板：成衣、布料、纱线的数量/成本/预算确认。
  交付给真实库存，不凭空刷新陈列。
- 制作订单选择款式/材料/数量；缺料阻止生产，取消不重复退料。
- 员工岗位优先级及休息策略；默认自动，允许玩家干预。
- 自动定价先保留，加全店折扣开关。让顾客预算判定与实收使用同一价格。
- 日结展示营业额、材料成本、毛利、成交/流失原因、库存与缺货提示。
- 验收：两种经营选择能在同一客流种子下产生可解释的不同结果。

## P2：可以保存、重新开始、完成目标

- 版本化本地存档：日期、金钱、逐件库存、材料批次、员工体力、
  家具位置及经营设置。先在闭店稳定点保存，避免承诺任意动画帧恢复。
- 写入临时文件后替换，保留上一份备份；损坏数据不得覆盖有效存档。
- 第一天给出一个小目标，例如完成指定成交数且保持现金为正。
  结算后可继续次日，不做无法退出的教程。
- 验收：关店存档后重开，金额/商品 ID/库存/体力一致；损坏存档可恢复。

## P3：生产反馈与民族服饰最小样本

- 织布与缝纫复用“拉凳→坐下→作业→起身→归位”的设施状态。
  动作就绪才生产；脚踏、手部、机器与布料推进同步。
- 补关键音效：脚踏/机针、织机、纸袋、支付；暂停、取消及离开设施能停止。
- 选一个有明确出处的服饰样本和一个小物文创配方，不把现有基础款随意命名为民族服装。
- 2D→3D 仅做一个稳定模板的颜色/纹样/装饰导入样本，保留设计来源和单品 ID。
  不将完整矢量编辑器、任意裁片生成或完整工艺模拟作为 MVP 前置条件。

## 暂缓但保留

大世界重建、更多房间、自由装修 UI、完整发展树、采风地图、复杂采购物流、
完整帽饰 DIY 编辑器、通用矢量工具及更多服装体型。
已有场景不删除；先保留接口，避免这些项目继续挤占营业闭环。

## 下一轮顺序

1. 审查本轮保存的表情候选代码并完成截图；处理休息过渡的失败回归。
2. 跑通固定种子的完整营业回归，先修阻塞交易的问题。
3. 实装营业状态、采购/制作决策与日结，然后做稳定点存档。

每轮最多推进一个核心功能；交付代码、测试结果和必要截图，
由开发日志子智能体追加记录，不以计划或生成了文件替代验收。
